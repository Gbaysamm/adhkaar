# Contributing

Jazakum Allahu khayran for helping. This page covers how to get started; how changes are reviewed and decided is in [GOVERNANCE.md](GOVERNANCE.md). Everyone taking part agrees to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Ways to help

### 1. Test on your phone (most needed)

Every Android brand handles background apps differently, so real-device reports are the most valuable contribution.

1. Install a build: `./gradlew installDebug`, or the APK from the latest CI run or release.
2. Go through onboarding and allow everything on the checklist.
3. In **Settings > Phone**, tap **Test morning**, then lock the phone. A session starts in one minute with your current mode.
4. Try again with the screen on and another app open, once for each mode (Gentle, Full screen, Lockdown).
5. Report what happened with **Settings > Report a bug** in the app, which fills in your phone, Android version, app version and mode, or use the [bug report form](../../issues/new?template=bug_report.yml). Say whether it opened on time when locked, with the screen on, and after a reboot, and in Lockdown whether other apps were covered and calls still worked.

### 2. Review or correct content

Adhkaar text, translations, references and the daily reminders are religious content and follow a stricter process: every change needs a source and a content reviewer's approval ([GOVERNANCE.md](GOVERNANCE.md#content-changes)).

- Found a mistake? Open a [content correction](../../issues/new?template=content_correction.yml) with the source.
- Adhkaar: `app/src/main/assets/adhkaar.json` and `collections.json`. Fields ending in `Evening` override the base text for the evening session. `AdhkaarContentTest` and `CollectionsContentTest` catch structural mistakes.
- Daily reminders are generated by `tools/reminders/build.py` and must never be edited by hand. See [docs/REMINDERS.md](docs/REMINDERS.md).
- Hijri dates: `app/src/main/assets/calendar/ng.json` is updated by a bot. See [docs/MOON_SIGHTING.md](docs/MOON_SIGHTING.md).

### 3. Translate

Interface text and adhkaar meanings are translated differently. See [docs/TRANSLATING.md](docs/TRANSLATING.md). Never use machine translation for religious text.

### 4. Record audio

See [docs/AUDIO.md](docs/AUDIO.md). Recordings need a clear licence and a tajweed check.

### 5. Code

- Open an issue first for anything larger than a fix, so we can agree on the approach.
- Kotlin + Jetpack Compose. Match the style of the surrounding code; values come from the design system in [docs/design/DESIGN.md](docs/design/DESIGN.md).
- Keep logic that doesn't need Android in pure Kotlin objects (like `SessionTimeCalculator`, `AlertPolicy`, `AllowList` and `AdhkaarWindows`) and unit test it.
- The safety rules in [PLAN.md](PLAN.md#safety-rules-these-cant-be-turned-off) are not negotiable. Calls and emergency access must always work, and there must always be a way out (a break, or the adhkaar time ending).
- No analytics, ads, trackers or new network requests. Anything that sends data off the phone won't be accepted.
- New permissions need a maintainer's agreement in an issue first: each one affects the Play Store review ([docs/LAUNCH.md](docs/LAUNCH.md)).

## Build and test

You need JDK 17 and the Android SDK (platform 36).

```bash
./gradlew assembleDebug                    # build
./gradlew testDebugUnitTest                # unit tests + screenshot rendering
./gradlew testDebugUnitTest -PnoScreens    # logic tests only
./gradlew lintDebug                        # lint
```

These are the same checks CI runs on every pull request.

**UI changes:** `testDebugUnitTest` re-renders the screenshots into `docs/screenshots/`. Commit the changed images with your PR so reviewers can see the difference.

## Pull requests

1. Fork, and branch from `main`.
2. Keep each PR to one change. Separate content changes from code changes.
3. Fill in the pull request template.
4. CI must pass. A maintainer reviews code; a content reviewer also reviews content (CODEOWNERS requests them automatically).
5. We squash-merge, so the PR title becomes the commit message: write it as a short sentence saying what changed.
